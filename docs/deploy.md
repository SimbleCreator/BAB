# Deploying B.A.B

Three pieces, each on any provider's free tier:

| Piece | What it is | Needs |
| --- | --- | --- |
| Frontend | static files from `frontend/dist/frontend/browser` | any static host with a "single-page app" fallback to `index.html` |
| API | the container from `backend/Dockerfile` | any container host that runs a Docker image and gives HTTPS |
| Database | PostgreSQL 14 or newer | any managed PostgreSQL with a connection string |

Nothing in the code is tied to a provider. Examples of free tiers people commonly use
change often, so check current limits before choosing: static hosts (Cloudflare Pages,
Netlify, GitHub Pages, Vercel), container hosts (Render, Fly.io, Koyeb, Google Cloud Run),
managed PostgreSQL (Neon, Supabase, Aiven).

## Recommended free setup: Cloudflare Pages + Render + Neon

No card is needed for any of the three (check each provider's current terms when you
sign up). The repository already contains what they need:

- `render.yaml`: the API service for Render (Docker, free plan, Singapore region; paths
  are relative to `backend/`, its root directory).
- `frontend/functions/api/[[path]].js`: a Cloudflare Pages Function that forwards
  `/api/*` to Render, so the browser sees one site and the login cookie works everywhere.
- `frontend/public/_headers`: security and caching headers for Cloudflare Pages.

Pick two names first. Here they are `bab-api` (Render) and `bab-app` (Cloudflare), giving
`https://bab-api.onrender.com` and `https://bab-app.pages.dev`. If a name is taken, the
provider shows the real address; use that everywhere below.

### Step 1: Put the code on GitHub

1. On https://github.com/new create a **private** repository named `bab`, with no README,
   .gitignore or licence.
2. Merge your work into `main` and push (replace `YOUR-USER`):

```bash
cd "/home/bharat/Bharaths_Personal/BAB APP" && git switch main && git merge --ff-only bounce-and-redesign
```
```bash
cd "/home/bharat/Bharaths_Personal/BAB APP" && git remote add origin https://github.com/YOUR-USER/bab.git && git push -u origin main
```

GitHub asks for your username and a personal access token (not your password) the
first time: create one at https://github.com/settings/tokens with the `repo` scope.
`.env` is ignored by git, so your keys are not uploaded.

### Step 2: Database on Neon

1. Sign up at https://neon.tech and create a project (name `bab`, Postgres 16 or newer,
   region **AWS Asia Pacific (Singapore)** to sit next to the API).
2. On the project dashboard click **Connect**, turn **Connection pooling off**, and copy
   the connection string. It looks like
   `postgresql://neondb_owner:...@ep-...-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require`.
   Paste it as is: the app converts it to its async driver form. Use the direct
   (non-pooled) string; the pooled one does not work with the app's driver.
3. Test it from your computer (it asks for the string without showing it):

```bash
cd "/home/bharat/Bharaths_Personal/BAB APP/backend" && read -rsp "Neon connection string: " BAB_DATABASE_URL && echo && BAB_DATABASE_URL="$BAB_DATABASE_URL" .venv/bin/python -m app.cli check-db
```

   `Connected. PostgreSQL ...` means it works. "No B.A.B tables yet" is expected: the
   API creates them on its first start.

### Step 3: API on Render

1. Sign up at https://render.com with your GitHub account and allow access to the `bab`
   repository.
2. Click **New > Blueprint**, pick the `bab` repository and branch `main`. Render reads
   `render.yaml` and asks for four values:
   - `BAB_DATABASE_URL`: the Neon string from step 2.
   - `BAB_FRONTEND_ORIGIN`: `https://bab-app.pages.dev` (your Cloudflare address).
   - `BAB_CONTACT_EMAIL`: the email shown on the privacy and terms pages.
   - `BAB_AI_API_KEY`: your OpenRouter key (`sk-or-...`), or empty to switch Bounce off.
   `BAB_JWT_SECRET` is generated by Render.
3. Click **Apply**. The first build takes a few minutes; the log ends with
   `Application startup complete` after the database migrations.
4. Open `https://bab-api.onrender.com/api/v1/health`: it shows `{"status":"ok",...}`.

### Step 4: Frontend on Cloudflare Pages

1. Sign up at https://dash.cloudflare.com, then **Workers & Pages > Create > Pages >
   Connect to Git** (if you only see the Workers flow, choose the Pages option on that
   screen). Pick the `bab` repository.
2. Build settings:

| Setting | Value |
| --- | --- |
| Project name | `bab-app` |
| Production branch | `main` |
| Framework preset | None |
| Root directory | `frontend` |
| Build command | `npm ci && npx ng build --configuration production` |
| Build output directory | `dist/frontend/browser` |

3. Environment variables (Production):

| Variable | Value |
| --- | --- |
| `NODE_VERSION` | `24` |
| `API_ORIGIN` | `https://bab-api.onrender.com` (your Render address, no trailing slash) |

4. **Save and Deploy**. Do not set `BAB_API_URL`: the app calls `/api/v1` on its own
   site and the Pages Function forwards it to Render.

If the Cloudflare address is not `bab-app.pages.dev`, set the real one as
`BAB_FRONTEND_ORIGIN` on Render (**Environment** tab; Render redeploys). If the Render
address changes, update `API_ORIGIN` on Cloudflare and redeploy (**Deployments > Retry**).

### Step 5: First sign-in and admin

1. Open `https://bab-app.pages.dev`, register and finish onboarding. The first request
   after the API has slept takes up to a minute (the jogger loader shows meanwhile).
2. Render's free plan has no shell, so run admin commands from your computer against the
   Neon database (paste the Neon string in place of `NEON_URL`):

```bash
cd "/home/bharat/Bharaths_Personal/BAB APP/backend" && BAB_DATABASE_URL='NEON_URL' .venv/bin/python -m app.cli make-admin you@example.com
```

The same way works for `reset-password user@example.com --generate`.

### Step 5b (optional): Sign in with Google

Free; needs a Google account. Only the client id is used (no client secret).

1. Open https://console.cloud.google.com, create a project (for example "BAB").
2. **APIs & Services > OAuth consent screen** (shown as **Google Auth Platform**):
   - User type **External**; app name "B.A.B"; your support email; developer email.
   - **Branding**: add the home page `https://beabeast.pages.dev`, the privacy page
     `https://beabeast.pages.dev/privacy` and terms `https://beabeast.pages.dev/terms`.
   - Scopes: none to add. Sign in with Google only uses `openid`, `email` and `profile`,
     which need no Google review.
   - **Audience**: press **Publish app** so anyone can sign in (while in "Testing" only
     the test users you list can).
3. **Clients > Create client**: type **Web application**, name "B.A.B web".
   - **Authorized JavaScript origins**: `https://beabeast.pages.dev`, plus
     `http://localhost` and `http://localhost:4200` for local development.
   - **Authorized redirect URIs**: leave empty (the button uses a popup).
4. Copy the **Client ID** (ends in `.apps.googleusercontent.com`).
5. Render > `bab-api` > **Environment**: add `BAB_GOOGLE_CLIENT_ID` with that value and
   save (Render redeploys). For local development put the same line in `backend/.env`.
6. Open the site: "Continue with Google" appears under the sign-in and register forms.

The site's security headers (`frontend/public/_headers`) already allow Google's sign-in
script and popup from `accounts.google.com/gsi/`.

### Step 6: Updates

Push to `main`: Render rebuilds the API when `backend/` changes and Cloudflare rebuilds
the frontend on every push. Migrations run automatically when the API starts.

### What the free plans mean for users

- The API sleeps after about 15 minutes without visitors; the next visit waits up to a
  minute while it wakes. Bounce plan requests take another 15 to 60 seconds.
- Neon's free database is small (well under 1 GB) and sleeps when idle; it wakes in
  about a second.
- OpenRouter free models allow about 50 requests a day per account, shared by all users.
- `FORWARDED_ALLOW_IPS=*` lets the login rate limit see real visitor addresses through
  the proxies. Someone calling the Render address directly could fake that header to
  dodge the limit; passwords are still protected by argon2 and the 10-character minimum.

## Reference

The sections below describe the general setup for any provider.

## 1. Choose the domain layout first (important)

The refresh token is an httpOnly cookie. Browsers increasingly block cookies between
different sites, so **put the frontend and the API on the same site**:

- **Recommended:** one domain you own, two subdomains, for example
  `app.example.com` (frontend) and `api.example.com` (API). Same site, so use
  `BAB_COOKIE_SAMESITE=lax`.
- **Also fine:** the static host proxies `/api/*` to the API (many static hosts support
  rewrites/proxies). The browser sees one origin. Build the frontend without
  `BAB_API_URL` and use `BAB_COOKIE_SAMESITE=lax`.
- **Avoid:** two unrelated provider subdomains (for example `myapp.pages.dev` and
  `myapi.onrender.com`). That needs `BAB_COOKIE_SAMESITE=none`, and Safari and other
  browsers may block the cookie, which signs users out on every reload.

## 2. Database

1. Create a PostgreSQL database and copy its connection string.
2. Change the scheme to the async driver: `postgresql+asyncpg://user:password@host:5432/dbname`.
   If the provider requires TLS, add `?ssl=require`.
3. Turn on the provider's automatic backups if the free tier has them; otherwise
   schedule a `pg_dump` (see "Backups").

## 3. API container

Build and run anywhere Docker runs:

```bash
docker build -t bab-api backend
```
```bash
docker run -p 8000:8000 --env-file prod.env bab-api
```

On a container host, point it at the repository's `backend/` folder (Dockerfile build)
or push the image to a registry it can pull from.

Environment variables (secrets go in the host's secret settings, never in git):

| Variable | Required | Example / notes |
| --- | --- | --- |
| `BAB_DATABASE_URL` | yes | `postgresql+asyncpg://user:pass@host:5432/bab?ssl=require`; a provider string such as `postgresql://...?sslmode=require&channel_binding=require` is converted automatically |
| `BAB_JWT_SECRET` | yes | 32+ random characters: `python -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `BAB_FRONTEND_ORIGIN` | yes | `https://app.example.com` (exact origin, https, no trailing slash) |
| `BAB_CONTACT_EMAIL` | yes | shown on the privacy and terms pages |
| `BAB_AI_API_KEY` | no | OpenRouter key (`sk-or-...`), or the key of another OpenAI-compatible endpoint; empty switches Bounce off |
| `BAB_AI_MODEL`, `BAB_AI_BASE_URL` | no | defaults `google/gemma-4-31b-it:free` and `https://openrouter.ai/api/v1`; any OpenAI-compatible endpoint works |
| `BAB_AI_FALLBACK_MODELS` | no | comma-separated backups tried in order when the main model is busy (OpenRouter only) |
| `BAB_AI_JSON_MODE` | no | `true` (default) asks for strict JSON; set `false` if an endpoint rejects it |
| `BAB_AI_TIMEOUT_S` | no | default 120 |
| `BAB_AI_DAILY_PLAN_LIMIT` | no | plans per user per 24 hours, default 5 |
| `BAB_COOKIE_SAMESITE` | no | `lax` (default) or `none` (see section 1) |
| `BAB_ENV` | set by the image | `production`: hides API docs, adds HSTS, refuses weak settings |
| `PORT` | no | most hosts set this; default 8000 |
| `RUN_MIGRATIONS` | no | `1` (default) runs `alembic upgrade head` on start; set `0` to run them yourself |
| `FORWARDED_ALLOW_IPS` | depends | IP(s) of the host's proxy so rate limits see real client IPs; `*` only if the container is reachable solely through that proxy |
| `BAB_ACCESS_TOKEN_MINUTES`, `BAB_REFRESH_TOKEN_DAYS` | no | defaults 15 and 30 |

The container refuses to start in production with the development secret, the
development database URL, or a non-https frontend origin.

Health check: `GET /api/v1/health` (also built into the image).

Run one container. Login and registration rate limits are kept in memory, so they only
work as intended with a single instance.

First admin (after the first sign-up), using the host's one-off command or shell:

```bash
python -m app.cli make-admin you@example.com
```

Password reset (no email in version 1):

```bash
python -m app.cli reset-password user@example.com --generate
```

## 4. Frontend

Build with the API address (skip `BAB_API_URL` when the static host proxies `/api`):

```bash
cd frontend && npm ci && BAB_API_URL=https://api.example.com/api/v1 npm run build:prod
```

Upload `frontend/dist/frontend/browser/`. On the static host:

- **SPA fallback:** serve `index.html` for unknown paths (so `/today` works on reload).
- **No caching for these files:** `index.html`, `ngsw.json`, `ngsw-worker.js`,
  `manifest.webmanifest` (`Cache-Control: no-cache`). Hashed `*.js`/`*.css` can be cached
  for a year.
- **Headers:** `frontend/public/_headers` sets these on Cloudflare Pages and Netlify
  (it assumes the API is proxied under `/api`; with a separate API origin, add it to
  `connect-src`):

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' data: https://tile.openstreetmap.org; connect-src 'self' https://fonts.googleapis.com https://fonts.gstatic.com https://tile.openstreetmap.org; manifest-src 'self'; worker-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), camera=(), microphone=()
Strict-Transport-Security: max-age=31536000; includeSubDomains
```

`'unsafe-inline'` for styles is needed by Angular's component styles; scripts stay
`'self'` only.

`connect-src` must list the Google Fonts and OpenStreetMap hosts: once the service
worker is active it fetches fonts and map tiles itself, and a worker's requests are
checked against `connect-src`. With `'self'` alone the icons show as words.

The service worker caches the app shell only. API responses are never cached. After a
new deploy, users get the new version on their next visit (the old one is replaced in
the background).

## 5. After the first deploy

1. Open `https://app.example.com`, register, finish onboarding.
2. Make yourself admin (above) and check the Admin page.
3. Install to the home screen from the browser menu and open it.
4. Check `https://api.example.com/docs` returns 404 (docs are development-only).
5. Review the privacy policy and terms placeholders, and the food values in
   `backend/app/content/foods.json`.

## Free tier caveats

- Free containers often sleep when idle; the first request after sleeping can take
  several seconds. The app shows its loading state meanwhile.
- Free databases have small storage limits. GPS tracks are capped at 2,000 points per
  run to keep rows small.
- OpenStreetMap tiles are free under the OSM tile usage policy (attribution is shown on
  every map). Heavy traffic needs a tile provider of your own.

## Backups

If the database provider has no automatic backups:

```bash
pg_dump --format=custom --no-owner "$DATABASE_URL_WITHOUT_ASYNCPG" > bab-$(date +%F).dump
```

Restore with `pg_restore --no-owner --dbname "$URL" bab-YYYY-MM-DD.dump`.
